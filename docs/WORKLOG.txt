Purpose
Make native Apple development telemetry useful with a familiar Xcode workflow.
Use the game as a repeatable workload for app and GPU investigations.

Implemented
Built a Metal falling-block game for macOS and iOS Simulator.
Added hold/swap, clear feedback, synthesized sound, and adjustable Aurora rendering.
Added an experimental native Swift package over the upstream OpenTelemetry SDK.
Direct OTLP export supports trusted development and tester builds.
Added runtime operation spans and five-second performance windows.
Added build identity and session IDs to join builds, game records, and captures.
Added optional host build observation, seeded replays, and Apple native capture commands.
Added an experimental MetricKit 27 reader with historical report context.

Workflow decisions
Ordinary Cmd-R uses one NeonStack scheme with LLDB and direct Swift export.
Removed redundant schemes. No relay or native observer starts during ordinary development.
The relay remains an optional transport experiment. It has no durable queue.
Native signposts stay available in Instruments. The SDK does not import arbitrary signposts.
Apple capture files remain local. Logfire receives metadata and selected measurements.
Native captures use explicit commands because they add overhead and can include other processes.

Native setup simplification
Added one Logfire.development client that owns MetricKit startup and lifecycle flush requests.
Moved frame windows and reusable Metal timing into the Swift package.
Added one state API that reports context to Logfire and Apple StateReporting.
Replaced the Python build phase with a host Swift identity script.
The script reads no credentials. The app exports identity when it starts.
Added the Swift logfire-apple companion with configure, doctor, capture, attach, and build actions.
Native sessions use a shared private marker directory. Capture resolves the latest verified live app.
Configure hides token input and writes a private runtime file. Existing credential files remain compatible.
Added exporter acknowledgement/failure counters. They do not promise complete delivery.
Expanded MetricKit selection to resource metrics, distributions, and diagnostic summaries.
Historical reports keep a separate exporter context. They do not inherit the current build or session.
Native summaries now include selected process memory, CPU times, disk I/O, and rendering state.
Full build observation remains optional and routes to the existing Python observer.

Experiments and issues
A Swift build tool plugin was considered for identity generation.
Kept the explicit host script for this iteration to avoid extra plugin/resource integration and trust setup.
The SDK itself does not require that script. Apps without it still export operation telemetry.
The initial iOS script inherited the Simulator sysroot. Explicit macOS host SDK selection fixes it.
Kept the existing Python build observer rather than duplicating its tested process and artifact handling in Swift.
Lifecycle flushing remains best effort. Background-task protection is not yet implemented.
Native capture still requires a live session. Historical PID reuse and rebuilt binaries need a separate attribution design.
