APPLE METAL + LOGFIRE

Purpose
Connect Apple performance evidence to a build and app session.
Status: experimental SDK and native companion for trusted developer and tester builds.
Log Roll, Flappy Log, and Neon Stack are reference consumers. Other apps can use the Swift package.
The reusable offering is the Swift SDK, native companion, and dashboard templates.
This community prototype is not an official released Logfire SDK.

Setup and verification
Use Xcode 27 with its Metal toolchain. Deep native Metal tools require macOS 27.
Use tools/install-companion.sh, then logfire-apple configure --region us.
Prototype users must configure again. The old credential location is retired.
The private runtime file is ~/.config/logfire-swift/credentials.env. It is not embedded in the app.
Enable LOGFIRE_DEV_DIRECT=1 in a development scheme. Press Command-R for normal iteration.
Use logfire-apple doctor --send to verify one acknowledged export.
Use tools/check-dev.sh for repository, game, Swift, and cached macOS Debug checks.
Add --smoke for a 12-second offscreen SDK session. No default profiler or Simulator run.
The scripts select one full Xcode and honor DEVELOPER_DIR without changing the global selection.

Data map
App operations, frame windows, responsiveness -> Swift SDK -> OTLP HTTPS -> Logfire.
SDK metrics -> nineteen fixed OTel instruments; only observed instruments appear in Logfire.
Rendering state -> SDK -> Logfire and Apple StateReporting.
Apple MetricKit -> SDK adapter -> historical diagnostic records when Apple delivers reports.
Whole-host CPU/memory/filesystem -> optional companion -> live records and selected metrics.
Apple layer/process measurements -> metalperftrace -> companion -> correlated summaries.
Shader compiler updates -> retained metalperftrace timeline -> post-run companion analysis -> correlated diagnostic records.
CPU recording -> Instruments trace -> offline export -> leaf functions, inclusive callers, and caller paths.
GPU workload capture -> gpudebug replay -> encoder/shader diagnostics.
Xcode build -> companion -> build span, task totals, selected host samples, and local xcresult.
Embedded build identity -> native build script -> SDK resource attributes and session marker.
App assertions -> DevelopmentScenario handshake -> runner lifetime control and report.
Retained report -> diagnose -> new local diagnosis without another app run.
Completed native recording -> diagnose --trace -> main-thread states, syscalls, and optional next-drawable waits; --publish explicitly sends them.
Identified SDK investigation windows -> raw native state intervals -> per-window coverage and correlated Logfire tables.

Terminology
SDK: Swift package for app-owned telemetry, state, frame windows, and optional Apple monitoring.
Companion: optional logfire-apple CLI for builds, host context, scenarios, and native captures.
OTLP: the OpenTelemetry wire format. The SDK exports directly over HTTPS. There is no relay or observer daemon.
Session: one app launch. A private marker links its PID, executable, start time, and build identity.
Build identity: ID, source fingerprint, commit, configuration, SDK, and Xcode version embedded at build time.
Source fingerprint: selected Swift, Metal, project, and package inputs. It is not a complete Xcode input manifest.
Signpost: native operation timing for Instruments. The SDK also emits a correlated Logfire span.
Presented FPS: cadence from confirmed Metal drawable timestamps. It differs from renderer callback cadence.
Partial window: retained samples at flush or context change. Regression comparisons use full windows.
StateReporting: named app workload state for Apple's measurements. It does not collect CPU stacks.
MetricKit: Apple-delivered historical metrics and diagnostics. It is not a live per-frame feed.
Capture manifest: original session/build identity, interval, binary, available symbols, and artifact checksums.
Structured details: JSON plus logfire.json_schema. Logfire stores a queryable object or array in record attributes.
Thread states: native running, blocked, runnable, and scheduling intervals. Normal waits are not automatically defects.
Scenario outcome: distinguishes assertions, evidence gaps, timeout, interruption, and process failure.
Regression gate: compares compatible Release runs and rejects missing or incompatible evidence.
Overview dashboard: fifteen panels for SDK sessions, live app signals, gameplay, builds, host context, and native evidence.
Chart buckets: five seconds with UTC timestamps. Dots show short observations; separate launches remain separate series.

Interpretation limits
Callback FPS differs from presented FPS. Optional drawable observation reports live presentation cadence. Preparation wall time differs from CPU utilization.
Main-queue delay and main-thread CPU independently observe responsiveness and activity.
GPU command duration is not hardware utilization. GPU replay is not live frame latency.
CPU sample weights describe running work. They do not establish waiting time or a root cause.
Profiled sessions are diagnostics, not clean baselines. Do not average window percentiles into a session percentile.
Builds have separate traces. Automated app sessions inherit the runner trace and correlate through build identity.
MetricKit retains historical dates and versions. It omits current session/build identity. Reports can overlap.
Raw captures and local reports remain on the Mac. Summaries and capture metadata reach Logfire.
Shader update fields describe native windows. Shader *_total fields are cumulative snapshots, not capture totals.
Compiler time differs from pipeline-call wall time. Pipeline reuse can bypass the compiler without a cached compiler event.
The exporter has no durable offline queue. Failed batches and abrupt stops can leave gaps.
Real MetricKit delivery, physical iOS, and a clean second-Mac setup remain unverified.

Current priorities
Graceful flushes now publish partial frame windows before exporter collection. Verify runner-requested and abrupt stops separately. Acknowledgement alone does not prove complete observation coverage.
SDK async spans inherit parent context across suspension and structured tasks. Detached tasks need explicit parent propagation.
The SDK target uses Swift 6. Audited bridges still cover synchronized upstream OTel types.
Trace and metric requests use gzip. An onscreen probe verifies 612 frame samples and 612 presentations in Logfire.
iOS requests finite background execution time for flushes. Physical-device behavior and credential provisioning remain unverified.
Keep GPU stage-boundary counters optional until profiling overhead and device fallback are verified.
Corroborate the coworker's MetricKit crash with its runtime version and crash stack.
Keep the short native development loop. Xcode CI remains deferred by request.
Preserve input limits and banner/trailing-data policies before consolidating the two JSON scanners.
Migrate command errors, report dictionaries, and public attribute types in focused compatible changes.
Investigate waiting/concurrency and startup evidence only when existing observations justify the capture.
Verify setup on another tester Mac before reusable release packaging and version tags.
Validate demand with Metal developers who already use Instruments or Tracy. Workflow convenience alone does not prove a market.
Keep the Swift SDK as the normal app integration. Test engine adapters for the same identity/assertion protocol before claiming broader support.

Product evidence
One historical Tracy issue documents friction with filenames, capture order, and repeated build comparisons.
https://github.com/wolfpld/tracy/issues/203
Tracy already supports build context, comparisons, CLI capture/export, and an optional MCP server in its current development tree.
https://github.com/wolfpld/tracy/blob/master/manual/tracy.tex
Apple recommends JSON profiling outputs for regression scripts and agents. Its tooling investment does not prove gaming market growth.
https://developer.apple.com/videos/play/wwdc2026/388/
Our hypothesis is a simpler Apple-native investigation flow with shared, correlated history in Logfire.
Build correlation and agent access alone are not unique. Raw artifact sharing remains an open gap.
